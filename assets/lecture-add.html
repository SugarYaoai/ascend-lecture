硬件物理基准 昇腾 910B 单核 AI Core 的 UB 片上物理标称容量约为 256 KB
上限: 256 KB / Core
16 Block 推荐方案

片上缓存安全充足

  • 每个 Block 负责 10752 个 float32 元素
  • 片上 UB 为 x、y、z 申请三段局部缓冲区
3 × 10752 × 4 B = 129024 B = 126 KB
静态缓冲区占用 126 KB / 256 KB 49.2%（安全）
8 Block 直觉反思

若仅切分为 8 个 Block

  • 每核处理数据量翻倍至 21504 个元素
  • 三段局部缓冲区静态内存占用随之翻倍
3 × 21504 × 4 B = 258048 B ≈ 252 KB
静态缓冲区占用 252 KB / 256 KB 98.4%（高危）
确定 Block 分配后，数据在单个 Core 内部按以下轨迹流动：

Host 与设备之间复制 →
Host 与设备之间复制 ←

Global Memory

当前 Block 的 z 片段写回 ←

UB

所有 Block 执行的都是同一份 Kernel 代码。硬件通过内置系统变量 block_idx（取值 0 到 15）区分不同的逻辑 Block：
C++ · GM 首地址偏移 单份 Kernel 多核并行 
constexpr uint32_t block_length = TOTAL_LENGTH / NUM_BLOCKS;

__gm__ float* x_gm = x + block_idx * block_length;
__gm__ float* y_gm = y + block_idx * block_length;
__gm__ float* z_gm = z + block_idx * block_length;
函数限定符语义
__global__ 可由 Host 启动的 Kernel
__vector__ 由 AI Core 内的 Vector 计算单元执行

Vector 计算单元无法直接对 GM 显存进行数学运算，必须在 UB 片上空间分配三段工作区：
C++ · 片上 UB 工作区 三段局部缓冲区声明 
__ubuf__ float x_local[block_length];
__ubuf__ float y_local[block_length];
__ubuf__ float z_local[block_length];

__ubuf__ 静态资源映射
✓ 编译期静态规划 编译器为整核预留 3 × 42 KB = 126 KB 硬件 UB 片上空间
✕ 运行时动态栈 非普通 C++ 局部数组在栈上动态申请
单核 Kernel 内部按“数据搬入 → 片上向量计算 → 结果写回”三阶段顺序执行，并通过同步原语保证数据就绪：
C++ · 三阶段执行流水 GM ↔ UB 搬运与同步 
// 4. 阶段一：数据搬入，GM -> UB。长度单位为 Bytes。
asc_copy_gm2ub(x_local, x_gm, block_length * sizeof(float));
asc_copy_gm2ub(y_local, y_gm, block_length * sizeof(float));
asc_sync();

// 5. 阶段二：片上向量计算。长度单位为元素个数。
asc_add(z_local, x_local, y_local, block_length);
asc_sync();

// 6. 阶段三：结果写回，UB -> GM。长度单位为 Bytes。
asc_copy_ub2gm(z_gm, z_local, block_length * sizeof(float));
asc_sync();
阶段一 · 数据搬入 (GM → UB) 单位: Bytes
block_length * sizeof(float) asc_sync()
阶段二 · 向量计算 (UB 片上) 单位: 元素个数
block_length asc_sync()
阶段三 · 结果写回 (UB → GM) 单位: Bytes
block_length * sizeof(float) asc_sync()
