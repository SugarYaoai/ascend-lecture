1.4.1 从 C API 到 C++ API 的重构三步法

1.4.1.2 UB 结构化分配

1 / 2
UB 侧不再使用三个 C 风格数组，而是通过 LocalMemAllocator 分配三个 LocalTensor<float>，分别保存当前 Block 的 x、y 和 z 片段。
第三节: C API 
__ubuf__ float xLocal[BLOCK_LENGTH];
__ubuf__ float yLocal[BLOCK_LENGTH];
__ubuf__ float zLocal[BLOCK_LENGTH];
本节: C++ API 
AscendC::LocalMemAllocator<AscendC::Hardware::UB>
    ubAllocator;
auto xLocal = ubAllocator.Alloc<float, blockLength>();
auto yLocal = ubAllocator.Alloc<float, blockLength>();
auto zLocal = ubAllocator.Alloc<float, blockLength>();
UB 工作区容量预算 3 × 10752 × 4 B = 129024 B = 126 KB

三段 float32 张量共占用 126 KB AI Core 片上 UB 工作区；局部资源的类型、长度与分配位置集中在一处，后续阅读 DataCopy 与 Add 时无需回溯数组地址和大小。

数据流仍遵循“搬入 -> 计算 -> 写回”三阶段；C API 需手动换算字节数，C++ API 则由 float Tensor 类型自动推导元素宽度。
第三节: C API 
asc_copy_gm2ub(xLocal, xGm,
    BLOCK_LENGTH * sizeof(float));
asc_copy_gm2ub(yLocal, yGm,
    BLOCK_LENGTH * sizeof(float));
asc_sync();

asc_add(zLocal, xLocal, yLocal, BLOCK_LENGTH);
asc_sync();

asc_copy_ub2gm(zGm, zLocal,
    BLOCK_LENGTH * sizeof(float));
asc_sync();
本节: C++ API 
AscendC::DataCopy(xLocal, xGm, blockLength);
AscendC::DataCopy(yLocal, yGm, blockLength);
AscendC::PipeBarrier<PIPE_ALL>();
AscendC::Add(zLocal, xLocal, yLocal, blockLength);
AscendC::PipeBarrier<PIPE_ALL>();

AscendC::DataCopy(zGm, zLocal, blockLength);
AscendC::PipeBarrier<PIPE_ALL>();
强类型元素长度

DataCopy 源与目的均为 float Tensor，blockLength 直接表示元素个数，彻底告别手动 sizeof(float) 换算。

核内流水线屏障

PipeBarrier<PIPE_ALL>() 作用于当前 Block / AI Core 内，确保输入写入 UB 后再由 Vector 单元读取，且计算完成后再写回 GM。
