1 / 6
本节对应 TensorOJ 题目，与传统算法在线评测平台类似：平台给出题目、测试数据和评测框架，提交后自动判断结果是否正确；不同之处在于，评测对象不再是普通 CPU 算法程序，而是面向昇腾 NPU 的算子实现。
共性机制

传统算法在线评测

  • 提供标准题目描述、测试用例与统一评测框架
  • 代码提交后自动编译运行并判断结果正确性
核心差异

CANNJudge 昇腾算子评测

  • 评测对象不再是普通 CPU 算法逻辑程序
  • 直接面向昇腾 NPU 硬件验证算子核函数实现

C++ · 固定规格静态执行参数 
constexpr uint32_t NUM_BLOCKS = 16;
constexpr uint32_t BLOCK_LENGTH = 10752;
constexpr int64_t TOTAL_LENGTH = NUM_BLOCKS * BLOCK_LENGTH;
总长度 172032
并行核数 16 Block
单核切片 10752 元素
限制 ① · 多核负载均衡

172032 个元素由 16 个逻辑 Block 均分，每个 Block 精确处理 10752 个元素。

限制 ② · 32 字节对齐

单段 float32 长度为 10752 × 4 B = 43008 B = 1344 × 32 B，严格满足 32 B 整数倍对齐。

限制 ③ · UB 容量预算

xLocal、yLocal、zLocal 三段缓冲共占 3 × 10752 × 4 B = 129024 B = 126 KB，约为 256 KB 标称容量一半，安全余量充足。

16 Block · 推荐安全方案

单核片上缓冲安全充足

  • 每核处理 10752 个 float32 元素
3 × 10752 × 4 B = 129024 B = 126 KB
126 KB / 256 KB 49.2%（安全）
8 Block · 翻倍高危反例

每核负载翻倍至 21504 元素

  • 三段 UB 局部数组静态占用随之翻倍
3 × 21504 × 4 B = 258048 B ≈ 252 KB
252 KB / 256 KB 98.4%（高危）
单个 AI Core 标称 256 KB UB 中，编译器控制信息与运行时框架均需占用片上资源；分配 252 KB（98.4%）极易在编译期检查或运行时直接失败，因此切分为 16 个 Block（126 KB）才安全可靠。
