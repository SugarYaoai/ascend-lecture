1.6 TensorOJ 实战：Add Medium 的双缓冲流水线

TensorOJ Add Medium · 性能优化篇
现状瓶颈 · 串行交替空转 01

硬件独立却被迫串行互等

  • Tile 循环虽已解决片上 UB 容量溢出，但 MTE 与 Vector 仍串行交替运行。
  • Vector 计算时 MTE 只能闲置；MTE 搬运时 Vector 只能等待，算力未饱和。
并发矛盾 · 单缓冲数据竞争 02

单套工作区无法安全预读

  • 消除空转的核心在于让「计算当前 Tile」与「搬运下一 Tile」同时进行。
  • 单缓冲区下直接预读会直接覆盖当前正在计算的片上数据，引发数据竞争。
破局方案 · 双缓冲乒乓机制 03

双套轮换 UB 并发重叠

  • 引入双缓冲 (Double Buffering)：开辟两套交替轮换的片上 UB 缓冲区（乒乓机制）。
  • 实现内存搬运与向量计算并发重叠，彻底拉满 AI Core 硬件算力利用率。
单缓冲串行执行（硬件交替空转） 串行互斥
[ MTE 搬运 ] → [ Vector 计算 ] → [ MTE 搬运 ]
双缓冲乒乓机制（计算与搬运同步推进） 并发重叠
